# 蛇形机器人树莓派—STM32 SPI 通信协议 V1

## 1. 目的与范围

本协议用于树莓派主控与 STM32F407 执行控制器之间的实时命令和状态交换。

- 树莓派负责 ROS 2、步态/规划和向 STM32 下发目标关节角。
- STM32 负责协议校验、急停、失联保护、关节限位和舵机执行。
- 本协议不传输图像、点云或大文件；这类数据不应经过 SPI 控制链路。

本文件是协议的唯一规范。树莓派程序和 STM32 固件必须使用相同版本的本文件。

## 2. 链路约定

| 项目 | 约定 |
| --- | --- |
| 主机 | Raspberry Pi |
| 从机 | STM32F407 的 SPI3 |
| SPI 模式 | Mode 0（CPOL=0，CPHA=0） |
| 数据宽度 | 8 bit，MSB first |
| 帧长度 | 固定 32 字节 |
| 字节序 | 多字节整数均为 little-endian |
| 初始时钟 | 100 kHz；稳定后可升至 500 kHz |
| 初始轮询频率 | 50 Hz；稳定后可升至 100 Hz |
| 片选 | Raspberry Pi CE0 连接 STM32 PA15 / SPI3_NSS |

SPI 是全双工协议：树莓派一次传输会同时写入一帧命令并读取一帧回复。STM32 返回的是它在**上一次事务结束后**准备好的回复，因此树莓派必须接受一帧状态延迟。

## 3. 物理连接

| Raspberry Pi 40 Pin | 信号 | STM32F407 |
| --- | --- | --- |
| Pin 23 / GPIO11 | SCLK | PC10 / SPI3_SCK |
| Pin 19 / GPIO10 | MOSI | PC12 / SPI3_MOSI |
| Pin 21 / GPIO9 | MISO | PC11 / SPI3_MISO |
| Pin 24 / GPIO8 / CE0 | NSS | PA15 / SPI3_NSS |
| Pin 6（或任意 GND） | GND | GND |

两侧 GPIO 均使用 3.3 V 逻辑并且必须共地。不得将 5 V 接入 Raspberry Pi GPIO。电机电源与逻辑电源的地也应遵循整机电源设计中的单点/低阻抗连接要求。

## 4. 帧格式

每一个 SPI 事务均恰好传输 32 字节。所有未定义或保留字段必须写 `0x00`，接收方必须忽略它们。

| 字节偏移 | 长度 | 类型 | 字段 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | `uint8` | `magic0` | 固定为 `0x53`（`S`） |
| 1 | 1 | `uint8` | `magic1` | 固定为 `0x52`（`R`） |
| 2 | 1 | `uint8` | `type` | 消息类型，见第 5 节；V1 不使用版本字节 |
| 3 | 1 | `uint8` | `page` | 请求或返回的遥测页，见第 6 节 |
| 4–5 | 2 | `uint16` | `sequence` | 序号，小端 |
| 6 | 1 | `uint8` | `joint_count` | `SET_JOINTS` 时固定为 `8`；其他命令为 `0` |
| 7 | 1 | `uint8` | `flags` | 命令/状态标志；V1 暂写 `0` |
| 8–23 | 16 | `int16[8]` | `joint_mrad` | 8 个关节目标或反馈，单位 milliradian |
| 24–27 | 4 | `uint32` | `aux0` | 随 `page` 变化的扩展数据 |
| 28–29 | 2 | `uint16` | `aux1` | 随 `page` 变化的扩展数据 |
| 30–31 | 2 | `uint16` | `crc16` | CRC16-CCITT，小端，覆盖字节 0–29 |

`joint_mrad[i]` 的物理值为：

```text
angle_rad = joint_mrad[i] / 1000.0
```

## 5. 消息类型

### 5.1 树莓派发送至 STM32

| 值 | 名称 | `joint_count` | 行为 |
| ---: | --- | ---: | --- |
| `0x01` | `PING` | 0 | 检查链路与在线状态，不改变电机状态 |
| `0x02` | `ENABLE` | 0 | 请求允许执行有效的关节目标 |
| `0x03` | `DISABLE` | 0 | 请求关闭所有舵机扭矩 |
| `0x04` | `SET_JOINTS` | 8 | 写入 8 个目标关节角；仅在 ENABLED 时生效 |
| `0x05` | `ESTOP` | 0 | 请求立即急停；优先级最高 |
| `0x06` | `GET_TELEMETRY` | 0 | 请求 STM32 准备指定 `page` 的遥测状态 |

### 5.2 STM32 发送至树莓派

| 值 | 名称 | 说明 |
| ---: | --- | --- |
| `0x80` | `ACK` | 成功确认上一条有效命令 |
| `0x81` | `TELEMETRY` | 由 `page` 决定是关节、IMU 或电流状态 |
| `0xFF` | `ERROR` | 最近请求被拒绝；`fault_flags` 给出原因 |

## 6. 遥测页、关节顺序与单位

32 字节帧不能在同一帧中同时放入 8 路关节数据、8 路电流和完整 IMU 数据。树莓派通过 `GET_TELEMETRY` 请求下列页面；STM32 在下一次 SPI 事务中返回 `TELEMETRY`。

| `page` | 名称 | 字节 8–23 | `aux0`（24–27） | `aux1`（28–29） |
| ---: | --- | --- | --- | --- |
| 0 | `JOINTS` | 最近一次被 STM32 接受的 8 个关节目标，`int16` mrad | 母线电压 mV（未接 ADC 时为 0） | 故障位 |
| 1 | `IMU` | `ax, ay, az, gx, gy, gz, temperature`，共 7 个 `int16` 原始值 | IMU 采样时间 ms | MCU 模式 |
| 2 | `SERVO_CURRENT` | 8 个舵机电流寄存器原始值，`int16` | 最近轮询完成时间 ms | 故障位 |

MPU6050 原始值的量程由 STM32 的初始化配置决定：本实现使用加速度 ±4g（8192 LSB/g）与陀螺仪 ±500 dps（65.5 LSB/(°/s)）。舵机电流使用厂家寄存器 `0x2E` 的原始有符号值；未完成与电流表的标定前，不得将其直接解释为 A 或用于过流保护阈值。

### 6.1 关节顺序与单位

V1 针对当前 4 个正交双轴模块、共 8 个自由度：

| 索引 | 逻辑关节 | 默认舵机 ID | 说明 |
| ---: | --- | ---: | --- |
| 0 | `module_1_yaw` | 1 | 从头部向尾部编号 |
| 1 | `module_1_pitch` | 2 |  |
| 2 | `module_2_yaw` | 3 |  |
| 3 | `module_2_pitch` | 4 |  |
| 4 | `module_3_yaw` | 5 |  |
| 5 | `module_3_pitch` | 6 |  |
| 6 | `module_4_yaw` | 7 |  |
| 7 | `module_4_pitch` | 8 |  |

默认舵机 ID 仅是当前固件的顺序映射。装配完成后，必须在 STM32 的映射表中记录每个关节的实际舵机 ID、方向（`+1` 或 `-1`）、零位偏移与最小/最大机械限位。上层 ROS 节点只使用本表的逻辑关节顺序，不直接依赖舵机 ID。

## 7. 状态与故障位

### 7.1 `mcu_mode`

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `DISABLED` | 上电默认状态，目标不会驱动电机 |
| 1 | `ENABLED` | 可接收有效 `SET_JOINTS` |
| 2 | `ESTOP` | 急停锁定；需要明确的 `ENABLE` 才可恢复 |

### 7.2 `fault_flags`

| 位 | 宏建议 | 含义 |
| ---: | --- | --- |
| 0 | `HOST_FAULT_BAD_CRC` | 收到 CRC 不正确的帧 |
| 1 | `HOST_FAULT_BAD_SEQUENCE` | 序号重复、倒退或异常跳变 |
| 2 | `HOST_FAULT_TIMEOUT` | 有效命令超时 |
| 3 | `HOST_FAULT_JOINT_LIMIT` | 目标角超出软件或机械限位 |
| 4 | `HOST_FAULT_ESTOP` | 急停已触发 |
| 5–15 | 保留 | 写 0 |

故障位是诊断信息。`ESTOP`、失联或超限时，STM32 的安全动作不能依赖树莓派是否及时读到了状态帧。

## 8. CRC 与序号规则

### CRC

- 算法：CRC16-CCITT；多项式 `0x1021`。
- 初始值：`0xFFFF`。
- 计算范围：字节 `0` 至 `29`。
- CRC 结果以 little-endian 写入字节 `30`、`31`。

STM32 固件当前的 `snake_spi::Protocol::Crc16()` 即为本协议所用的 CRC 实现。树莓派必须使用相同算法。

### 序号

- 树莓派从 `0` 开始，每发送一帧命令加 `1`，按 `uint16` 自然回绕。
- 同一个序号重发是允许的，但 STM32 不得重复执行有副作用的命令。
- `ESTOP` 即使序号异常也应执行；其余命令序号错误时仅返回 `ERROR`。
- `ACK`、`STATUS`、`ERROR` 的 `sequence` 填对应的已处理命令序号。

## 9. 安全状态机

```text
上电 ───────────────→ DISABLED
                         │
                    ENABLE（有效）
                         │
                         ▼
                      ENABLED
                   ┌─────┼──────┐
            SET_JOINTS  DISABLE  超时/超限/ESTOP
                   │       │             │
                   └───────┘             ▼
                      保持 ENABLED     DISABLED 或 ESTOP
```

具体规则：

1. STM32 上电后必须处于 `DISABLED`。
2. 只有处于 `ENABLED` 且 CRC、序号、关节数量、限位均有效时，`SET_JOINTS` 才可更新目标。
3. 如果 150 ms 内未收到有效的 `PING` 或 `SET_JOINTS`，STM32 必须停止更新目标并关闭舵机扭矩，置位 `HOST_FAULT_TIMEOUT`。
4. `DISABLE` 必须关闭全部 8 个舵机扭矩。
5. `ESTOP` 必须立即关闭全部 8 个舵机扭矩，并置 `mcu_mode=ESTOP` 与 `HOST_FAULT_ESTOP`。
6. 树莓派重启、ROS 节点退出或 SPI 断线时，最终安全决策仍由 STM32 完成。

## 10. 一次事务示例

树莓派已使能，当前希望将所有关节设置为 0 rad：

```text
请求：
53 52 04 00 2A 00 08 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00
CC CC
```

其中 `0x2A` 为序号 42，最后两个字节 `CC CC` 在这里仅代表“由 CRC 算法计算出的结果”，不是固定值。

同一次 SPI 事务中读到的通常是上一帧状态。下一次事务中，STM32 应返回序号为 42 的 `ACK` 或 `STATUS`。

## 11. 上电与验收顺序

1. 不接舵机电源，验证 `PING → ACK`。
2. 验证 CRC 错误帧不会改变 STM32 状态。
3. 验证 `ENABLE → ACK`、`DISABLE → ACK`。
4. 验证停止树莓派轮询后约 150 ms 内 STM32 进入安全状态。
5. 仅连接一个机械固定的舵机，测试很小的 `SET_JOINTS` 角度。
6. 依次扩展至全部 8 个关节。
7. 最后才将树莓派 SPI 客户端封装为 ROS 2 的 `snake_hardware` 节点。

## 12. 版本演进规则

- V1 无协议版本字节；帧头、长度、CRC 和消息类型共同识别协议。
- V1 不再增加新的可执行语义到保留字段；需要不兼容修改时使用新的帧头或新的协议文档。
- 扩展关节数超过 8 时，不修改 V1 的 32 字节帧，应定义新的协议版本。
